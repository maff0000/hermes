# GOLD-AUD-A: disposition table

Required by the CA/PO legacy application doctrine (2026-10-15). Format: `PORTFOLIO.md` section 7.4 in the GOAL repository. Every verdict is a **recommendation only**: nothing is retired, shut down, migrated or mutated by this audit, and any physical retirement needs a separate authorised work order. The objective is the strongest GOLD MVP architecture, not maximum reuse. Adjudication of verdicts is DR-37.

Sources: `maff0000/hermes` @ `ca1901789f8c7a7e085d02ebde8f7264d90d669e`; `maff0000/HELIOS` @ `7f7193d55475e40583892b94dd461b1b64d6f1ef`.

**Generation** is judged from file content and git dates, not from deployment (which is UNVERIFIED). "Newer canonical" means the governed `:v1` contract family; "legacy" means the unversioned `signals:` and `market_map` generation.

**Cost basis.** Engineering cost is in person-days (PD), a PL estimate from lines of code, the number of existing test files and the amount of integration, not a commitment. "Reuse" is cost to adopt as is, "refactor" to modify, "clean" to build anew to the same standard including tests. Estimates are order-of-magnitude (plus or minus 50 percent).

**Criteria abbreviations.** Fit = architecture fit with the current architecture; Quality = code quality; Det = determinism; Test = test evidence (what is proven by the cited tests; this PL did not run the suite, CI success on the revision is recorded in `AUDIT-2026-10-16.md` section 0.2); Maint = maintainability; Contract = contracts; Ops = operational dependencies; Integ = integration cost.
